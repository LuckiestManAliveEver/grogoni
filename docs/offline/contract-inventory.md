# Contract inventory

Audited against the checked-out repository, September 2026. The plan’s Prisma schema and execution-fabric resolver no longer exist. Authoritative models are shared-types summaries, domain maps in Cp2Store, and infra/db SQL migrations. Route-derived names below are proposals, not claims of existing RPC endpoints.

The API boundary is apps/web/src/lib/api.ts; api-helpers and api-request-cache feed the chat drawer hooks. Direct fetch consumers include inference/remote-provider.ts, sync/sync-client.ts, messaging and authentication. Those are explicitly cloud-only unless separately documented. This inventory conservatively includes the complete static API route surface, including administration routes not necessarily called by chat.

Existing offline handling: local-data-repository is a stale-read cache; sync/indexeddb-repository and sync-core provide a separate legacy mutation queue. New deliberate offline sessions use offline-runtime exclusively.

## Model mapping and gaps

Catalogue touches products, productFieldSchemas, inventoryMovements; customers touches customers; invoices/orders touch invoices, publicOrders and products; conversations touch conversations, participants and messages. All other route models are defined in the named domain store and are excluded from the mirror. Auth credentials, payment settlement and marketplace checkout remain cloud-only. Receipt OCR is now split: capture and text extraction (`receipts.ocr.create`/`receipts.ocr.list`) run on-device via tesseract.js and mirror into a new `receiptOcrJobs` local table (push-only - never pulled back down); supplier/sales-agent matching and confirmation still require supplier/sales-agent data this device's snapshot does not carry. The local write subset is product create/update, stock count, customer create, receipt-OCR capture, and invoice create/update/confirm; order snapshots stay read-only (they originate from public storefront checkout, which is cloud-only). Cart is UI state, not a Prisma table.

On-device AI inference is real but narrow: one pinned model (`Qwen2.5-0.5B-Instruct-q4f16_1-MLC` via `@mlc-ai/web-llm`/WebGPU), answering from the prompt alone with no catalogue/order/customer/account data - see `docs/offline/README.md`'s "On-device AI" section. Conversation messages are the only peer-capable prototype contract; no business operations may be sent to peers.

## Coverage risk

Static app routes are fully enumerated; dynamic runtime tools, MCP dispatch and third-party callbacks require their domain permissions and remain cloud-only. The Python receipt OCR service (`OCR_WORKER_URL`) stays the cloud engine used when a device is online; offline text extraction instead runs tesseract.js entirely in-browser, an independent implementation, not a client of that service. Hosted inference internals and native Android BLE radio behavior remain non-browser-local. No cloud schema is inferred from a nonexistent Prisma file.
