# Instant messaging: what remains (2026-11-19)

Status after `fb45130f` (deployed: Edge API and grogoni.com). This list supersedes the open items of the [original checklist](instant-messaging-checklist-2026-11-17.md) and the [implementation report](instant-messaging-implementation-2026-11-18.md). Each item says how to tell it is done. Evidence was checked against the code and tests on 2026-11-19; "untested" means the behavior exists in code but no test proves it.

## 1. Performance (blocks "instant")

- [ ] **Decide on snapshot query planning.** The `load` stage (165-190 ms warm) is mostly PostgreSQL planning a 154-arm `UNION ALL` on every request. The fix (parameterized SQL plus prepared statements through Neon's pooler, so plans are cached) is a production-risk change. Needs a decision first. Done when: `load` under 50 ms in `Server-Timing`, the full PostgreSQL lane is green, and there are no `prepared statement` errors in Edge logs for 24 h.
- [ ] **Measure acknowledgement from a Kenyan network.** All live numbers so far come from one machine with unstable connectivity. Run `scripts/measure-instant-messaging.mjs --live` from Safaricom and Airtel mobile data. Done when: before/after rows from a Kenyan network are in the audit doc.
- [ ] **Decide the Edge region if Kenya acknowledgement stays above 1 s.** Functions are pinned to `us-east-1` next to Neon `us-east-2`. Options: a closer region for both, or accept the network floor. Done when: decision recorded with measurements.
- [x] **Measure inbound visibility.** Write a two-account harness: account A sends, and we time until B's open thread shows the message (SSE hint → delta read). Done when: the p50 and p90 are in the audit doc against the < 1 s target. **Done (2026-11-22, production after `7f5e5a36`):** `scripts/measure-inbound-visibility.mjs --live`, 10 samples, two disposable accounts on grogoni.com from this machine: p50 6,575 ms, p90 15,574 ms (range 4,536-15,574 ms) against the < 1 s target: **not met**. The path is the sender's POST being accepted (it writes the journal row), the hint (at most 0.5 s), then the receiver's delta read. From this connection each API round trip measured 2.2-3.4 s, so two of them account for the median; the outliers match this connection's instability. The next measurement that decides it is the same script from a Kenyan network (item above), and then the region decision. Fixtures removed by the script's cleanup (no error).
- [x] **Load-test the hint stream.** Every open SSE stream re-checks the session and queries the journal every 500 ms, about 2 transactions per second per connected user. Done when: database CPU and Edge cost are measured at 100 and 1,000 concurrent streams, and the interval or design is adjusted if needed. **Done 2026-11-20:** `scripts/measure-hint-stream-load.ts` against local PostgreSQL 16 (this machine, not Neon): rechecking the session on every 500 ms probe cost 3.97 transactions/s per stream at 100 streams and 3.84 at 1,000; the stream now rechecks the session every 5 s (journal still every 500 ms), giving 2.25 and 2.18 (−43%), transaction p95 10.5 ms and 8.0 ms. Revoked sessions stop within 5 s (`tests/message-event-stream.test.ts`). Neon CPU and Edge cost at this scale still need a production-like run.

  Follow-up (2026-11-21): a one-query probe (session check folded into the journal read) was measured locally against the production stream code (raw results in `/tmp/hint-stream-load/`) and not kept: PostgreSQL CPU per probe is dominated by planning each query (warm: 1.50 ms planning against 0.25 ms execution), so re-planning the session join every 500 ms costs more than this 5 s recheck. The same planning cost is the root of **Decide on snapshot query planning** above.

- [x] **Decide the idle fallback cadence.** The remaining 9 requests per minute are the stream reconnect, the deliberate 30 s fallback checks (sync, inbox, open conversation), the notifications poll and a health check. Done when: the cadence is decided, for example a longer fallback while push is healthy. **Done (2026-11-21):** Kept at 30 s while push is healthy. While the stream reports healthy, the fallback is the only guard against a stream that stays open but stalls (for example a buffering proxy), and it costs about 2 small requests per minute. Revisit once the stream carries a heartbeat the client checks.
- [ ] **Watch isolate retirement.** Isolates now serve about 7 requests before `EarlyDrop`. Done when: a saved logs query (`SELECT log_attributes['reason'], count() … event_message = 'shutdown'`) is reviewed after a day of real traffic and the median requests per isolate is recorded.

## 5. Known follow-ups (from the 2026-11-21 reviews, not blocking)

- [x] **Customer inbox listing on Edge does not deliver a shop reply.** On Edge a customer's inbox listing and thread open do not load the shop's memberships, so only the customer's sync pull marks a shop reply delivered (it does, verified). Delivery therefore needs the sync pull running (IndexedDB available, sync database not superseded). Done when: the listing path loads memberships for the caller's shop conversations too, with a PostgreSQL test. **Done (2026-11-22):** `deliveringRead` in `edge-snapshot-scope.ts` loads the shop's memberships for the inbox listing and a thread open as well as the sync pull; `tests/edge-delivered-postgres.test.ts` proves both on PostgreSQL and `tests/edge-delivering-read-scope.test.ts` keeps other paths narrow.
- [x] **Kept sends are left out of on-device model history.** A send carried across a stale thread read is marked as this device's copy until a read includes it; `inferenceHistory` skips such copies, so a browser or owner-node model request in that window can miss the previous turn. Done when: kept sends count as history, with a test. **Done (2026-11-22):** `outboxPlaceholders` marks a carried send `keptSend`, and `inferenceHistory` counts it unless it has failed; `tests/user-journey-fixes.test.tsx` ("counts a kept send").
- [ ] **In-memory Node API runs a resent turn twice.** Without queued turns (memory mode, development only), a resend that arrives while the first turn runs starts a second inference. Done when: memory mode reuses the running turn.
- [x] **A blocked sync database disables sync for the session.** An older-version tab blocking the upgrade now fails fast with no retry. Done when: the sync repository retries after the blocking tab closes. **Done (2026-11-22):** `openSyncRepositoryWhenFree` (`apps/web/src/sync/open-when-free.ts`) retries a `SyncDatabaseBlockedError` at 2 s, 5 s, 10 s, 30 s, then every 60 s, and tells the person once to close the old tab; `tests/sync-open-when-free.test.ts`.
- [ ] **Outbox after a slow or failed device-database open.** A page-load pass that ran on the local-storage fallback counts as done, so entries the late open brings in wait for their own backoff (up to 2 minutes); a failed or blocked open is not retried in the session (main retried on the next send); when a newer build takes the database, the older tab's moved entries vanish from its view (the newer tab sends them). Done when: the load pass reruns after a late adoption, the open is retried, and the older tab keeps its view, each with a test. **Partly done (2026-11-22):** a late adoption dispatches `messagingOutboxAdoptedEvent` and the load pass reruns (`useInboxRefresh`); a failed or blocked open is retried 30 s later on next use, never after a newer version took the database (`tests/outbox-storage-resilience.test.ts`). Still open: the older tab's view of entries it moved. Keeping a copy would show them waiting after the newer tab sent them; it needs the newer tab's removals, over the outbox BroadcastChannel, to reach the older tab.
- [x] **Another open tab's entries count as left by an earlier page.** The page-load pass resends them without their backoff; the server dedupes by clientMessageId. Done when: entries carry the tab that queued them and a live tab's are left to it. **Done (2026-11-22):** each page holds a `grogoni-outbox-page:<id>` Web Lock while open and tags what it queues (`queuedBy`); the load pass leaves a live tab's entries to it, unless they are more than 5 minutes past due (that tab switched account or is frozen). The lock is released on `pagehide` so the page can still enter the back/forward cache, and taken again on `pageshow`. Without Web Locks the old rule applies. `tests/outbox-live-tab-entries.test.ts`.
- [ ] **Account hints after a 401, kept copies' Reply/Delivery attempts, a never-finishing chat open** (each described in the review reports in `/tmp/instant-messaging/critique/`).
