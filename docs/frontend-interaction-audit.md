# Frontend interaction audit

Audit date: 2026-07-17

Scope: `apps/web/src`, its public/legal routes, and the Fastify contracts used by the web app.
Counting rule: one row is one visible interaction class. Repeated list-row controls (for example, one Edit button per product) count once because they execute the same component handler and contract. Form fields are included with their submit action when they have no independent side effect.

## Architecture and baseline

- Framework: React 19 rendered by Vite 6. There is no routing library. `AppRouter.tsx` selects legal, public storefront, and owner routes; `GrogoniApplication.tsx` contains the owner application while account restoration and async-action behavior live in focused feature/hook modules.
- Navigation: the header, chat cards, and generated detail cards call `setView` or set nested card state. `/agent/:agentId`, `/terms`, `/privacy`, and `/account-deletion` are the only refresh-safe paths at baseline.
- Authentication: custom Fastify sessions and PINs; email OTP uses the CP2 API. Phone OTP is
  rejected, and compulsory first-shop phone capture is stored as an unverified private identity
  attribute. Session cookies are sent by the shared JSON helpers.
- State: React local state, local/session storage for the saved owner/shop/agent and OAuth continuation, IndexedDB for sync, and a local message outbox. There is no global state library.
- UI feedback: inline notes and `statusMessage`; at baseline `statusMessage` is rendered only on authentication/setup panels. There is no toast primitive.
- Backend: Fastify routes in `services/api/src/cp2/routes.ts`, with tenant/session enforcement in `services/api/src/cp2/store.ts` and the Postgres store. Business mutations use business-scoped endpoints.
- Tests: Vitest integration/contract suites and Playwright responsive/accessibility coverage.
- Baseline test command: `pnpm test` (started before implementation; final result is recorded in the completion report).

## Safety notes

- The API store authorizes business routes from the session and business membership; frontend identifiers are not treated as authorization.
- Public storefront reads are explicitly public and return a bounded product projection.
- Account deletion revokes all sessions and blocks business access immediately. A PIN login may enter only the recovery flow until the owner re-verifies the PIN and restores before the 30-day deadline.
- Invite creation persists a queued outbox record; it deliberately does not mark an invite sent until an external delivery provider confirms it.
- Public file messages persist bounded attachment names as metadata only; the UI explicitly states that file contents are not uploaded by this contract.
